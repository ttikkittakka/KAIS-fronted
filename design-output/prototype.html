오늘의 상태

기록한 날짜와 돌봄을 따로 보관합니다. 쉬어도 사라지지 않고, 기분에 따라 줄어들지 않아요.

캐릭터가 중심

한 가지를 해도 충분합니다. 세 가지 완료는 축하하지만, 모두 하도록 재촉하지 않아요.

05 — INTERACTION CONTRACT

오늘의 상태와 성장, 서로 다른 두 가지.

사용자 행동앱 이벤트기존 Rive 연결보관하는 의미
기록 완료checkin_savedidle / low_energy + 첫 기록일에 new_leaf 뿅날짜별 기록 1개. 좋은 기분 여부와 무관.
작은 행동 하나 완료care_completed잎만 통통을 한 번 재생한 뒤 오늘 상태 복귀완료 ID를 추가. 같은 행동 중복 적립 없음.
세 가지 완료all_care_complete통통 · 원본 반짝임 포함 · 2.35초컨디션을 좋음으로 덮어쓰지 않음.
다른 날에도 기록new_recorded_daynew_leaf 뿅 · 2.25초, 초기 MVP는 성장 반응으로 사용연속 여부와 상관없이 날짜별 흔적 누적.
다시 방문app_resume저장된 오늘 상태 + idle메인 진입. 오늘 기록을 확인한 후 돌봄 이용.

실제 지원 범위

Artboard 1: 500×500. State Machine 5개, Timeline 10개. Boolean / Number / Trigger Input은 모두 0개입니다.

care_1_complete 같은 이름은 앱 이벤트로만 정의합니다. 원본에 없는 Input, 꽃, 영구 성장 단계, 정원 확장 애니메이션은 구현된 것으로 표시하지 않습니다.

회복 표현의 안전한 범위

클리어버전1·클리어버전2가 있지만, 개별 잎 색·구름·각도를 독립 조절하는 Input은 없습니다. 초기 MVP는 원본 ‘잎만 통통’을 완료 반응으로 사용합니다.

행동을 했다고 사용자의 실제 기분이 회복됐다고 단정하지 않습니다. ‘조금 돌봤어요’라는 피드백으로 응답합니다.

06 — UX AUDIT

잘하는 날만 남는 정원이 아니도록.

설계에 반영

  • 기록 전 돌봄 진입 차단 및 저장 성공 후 이동
  • 숫자 점수·연속 기록·랭킹·진단 표현 없음
  • 48px 터치 영역, 선택 상태 텍스트/체크 표시
  • 수정 가능한 선택과 명시적인 다음 버튼
  • 메모는 선택 사항, 저장 실패 시 내용 유지
  • 모션 중지와 시스템 reduced-motion 지원

개발 인계 시 확인

  • 375px·가로 화면·200% 텍스트에서 실기기 QA
  • VoiceOver / TalkBack 읽기 순서 및 포커스
  • Rive State Machine의 내부 transition 시각 검수
  • 성장 지속 표현은 원본 에디터에서 지원 범위 합의
  • 사용자 계정 도입 시 기록을 계정별 분리
  • Figma 네이티브 재생과 실제 Rive 재생을 구분
UIUXProMax 기준을 검토해 모바일 자기돌봄 맥락에 맞게 선택 적용했습니다. Rive 원본 파일은 수정하지 않았습니다. Figma 생성 코드는 준비되어 있으며 실제 파일 생성은 팀 선택 대기 중입니다. 이 프로토타입은 실제 Rive 재생을 담당합니다.
